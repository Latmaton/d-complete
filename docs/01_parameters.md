# Mathematical meaning and complete record of the parameters

`parameters.py` is the sole source of all fixed inputs. The Markdown and CSV files in `supplement/` are generated by `export_parameters.py` for reading and cross-checking. The main verification program does not read these exported tables or treat height distributions, terminal counts, or density values from previous runs as trusted inputs.

The fixed inputs are choices to be checked. An actual run must construct valid residue families, compute terminal lower bounds, and verify the required strict inequalities. Checking that the parameter tables are complete does not establish the paper's conclusions.

## 1. Mathematical parameters for each base pair

The field order in `PARAMETERS[(p,q)]` is

```python
(d, B, ell, z, C, m0, t_max, J, target)
```

The lists `B` and `ell` have the same length. Entry `i-1` corresponds to position `i` in the mathematical period.

| Parameter | Mathematical meaning and role | Main verification location |
| --- | --- | --- |
| `p,q` | Ordered signed bases, with absolute values greater than 1 and relatively prime | `arithmetic.read_inputs` |
| `d` | The first exponent in a residue family satisfies `0 <= alpha < d` | Input checks and the constructions in `residues` |
| `P=abs(p)**d` | The modulus whose residue classes must be covered; it is not the upper bound of an integer scan | Residue coverage checks, tail bounds, terminal lifting |
| `B[i-1]` | An upper bound on the absolute rational sum of each chain in residue family `i` | `residues.verify_family`, or a uniform size bound when applicable |
| `ell[i-1]` | The positive integer height budget at step `i` | `arithmetic.constants`, `arithmetic.tails` |
| `s=len(B)` | The period length, equal to `len(ell)` | Input checks |
| `z` | The exact rational parameter in the exponential moments; it must exceed 1 | Input checks and `arithmetic.tails` |
| `C` | A chosen upper bound on `Lambda_s` in the paper, not an assumed value of that quantity | `arithmetic.tails` checks `Lambda_s <= C` |
| `m0` | The number of complete periods used to improve the tail bounds | `arithmetic.tails` |
| `t_max` | The largest retained tail index | `arithmetic.tails` |
| `J` | The number of terms `j=0,...,J-1` used in density lifting | Interval choice lengths and `arithmetic.density` |
| `target` | The internal threshold that the final exact lower bound must exceed strictly | `arithmetic.density` |

The constants are computed as

\[
c=\frac{|q|^{\ell_1+\cdots+\ell_s}}{P^s},\qquad
A=\frac1{1-c}\sum_{i=1}^s
\frac{B_i|q|^{\ell_i+\cdots+\ell_s-1}}{P^{s-i+1}}.
\]

The program requires `c < 1`. After constructing the residue families, the exponential-moment and tail-bound calculation also requires the product of the moments over one period to satisfy `g < 1`. Both conditions must hold before the subsequent lower bounds can be used.

The quantities `C`, `A`, and `c` are distinct. In the code, `C` is the supplied upper bound for the tail constant, whereas `A,c` are computed from the other inputs.

## 2. Three different notions of height

| Notation or field | Meaning |
| --- | --- |
| Residue-family height `a` or `h(r)` | One plus the largest `gamma` in a rational chain of terms `p**alpha/q**gamma`; the empty chain has height 0 |
| Scale field `H`, or `h` in a terminal request | The height bound for an integer antichain representation, namely one plus the largest second exponent |
| `HEIGHT_LIMITS[(p,q)]` | The finite height limit used to search for residue families; this is an implementation limit |

These quantities are not interchangeable. For example, the residue search height limit for `(5,2)` is 31, whereas the fifth terminal step for positive bases stores heights up to 134. The latter is not restricted by 31.

`HEIGHT_LIMITS` is 31 for `(5,2)` and 50 for the other seven cases. If the finite search does not cover every residue, the program cannot proceed to certify the density. Increasing this limit only widens the search for candidates; it does not automatically prove that new families satisfy the size bounds or exponential-moment conditions.

## 3. All scale choices `(H,X,n,e)`

Row `i-1` of `SCALES[(p,q)]` records scale `i` as

```python
(H, X, n, e)
```

| Field | Role |
| --- | --- |
| `H` | The terminal height bound used at this scale |
| `X` | The actual radius for terminal counting, expressed as an exact integer or rational number |
| `n` | The scaling exponent used to divide by `abs(p)**n` when constructing the scale coefficients |
| `e` | Used only for `(5,2)` to select the terminal interval table with exponent `nu_m=e` |

**The roles of `n` and `e` are different.** Some scales for positive bases use the fifth terminal table, with `e=57`, but have scaling exponent `n=56`. In the general signed cases, `e=0` is a placeholder; it does not mean that the terminal radius is 1 and does not select an interval table for positive bases.

For each scale, the program requests

\[
(h,X)=(H-v,X),\qquad 0\leq v<\min(H,t_{\max}).
\]

Let `t[h,X]` be the constructed terminal lower bound, and put

\[
\beta_i=\sum_{v=0}^{\min(H_i,t_{\max})-1}
(w_v-w_{v+1})t[H_i-v,X_i].
\]

The scale coefficients are generated by `arithmetic.scale_coefficients`; they are not inputs in the parameter tables. With the common grid denominator `D0=10**9`, the program uses

\[
a_i=\frac{\left\lfloor D_0|p|^{-n_i}
(A|q|^{H_i}+X_i)\right\rfloor+1}{D_0},
\]

\[
b_i=\frac{\left\lfloor D_0^2|p|^{-n_i}\beta_i\right\rfloor}{D_0^2}.
\]

The first formula adds 1 even when the scaled value is an integer, ensuring that the result lies strictly above the required boundary. The second rounds down to avoid overstating the counting lower bound. The program also checks `b_i > 0`.

## 4. Interval endpoints and choices `(i,k)`

Each row of `INTERVALS[(p,q)]` records

```python
(left, right, [(i_0,k_0), ..., (i_{J-1},k_{J-1})])
```

- `left,right` are interval endpoints for the normalized variable, all expressed as exact rational numbers.
- The choice `(i_j,k_j)` for term `j` selects scale `i_j` and multiplies by `abs(p)**k_j`.
- Scale indices `i_j` start at 1; summation positions `j` start at 0.
- Scaling exponents `k_j` may be negative. Calculations must use exact fractions, without evaluating negative integer powers as floating-point numbers.

`arithmetic.density` checks that the intervals are contiguous, that each interval has exactly `J` choices, that all scale indices are valid, and that the final endpoint is exactly `abs(p)` times the first endpoint. It then evaluates the density-lifting formula from the paper at both endpoints of every interval. Covering a complete period is necessary for the proof to apply at all sufficiently large scales; checking only selected points is insufficient.

Each row of `intervals.csv` in a case directory under `supplement/` contains all choices for that interval. The file `choices.csv` expands the same information into `(v,j,i,k)` rows for individual checks. Both are generated from the same source data.

## 5. Paper targets and internal targets

`PAPER_TARGETS` records the thresholds stated in the paper. The final field of `PARAMETERS` retains the internal threshold used by the original program.

| Bases | Paper target | Internal target |
| --- | --- | --- |
| `(5,2)` | `9/10` | `9001/10000` |
| Other seven cases | See the complete case tables | Equal to the paper target |

Neither target is a pre-recorded computation result. A case can be reported as passed only when the computed exact density lower bound strictly exceeds its internal target. The slightly stronger internal target for `(5,2)` also implies the paper's bound `>9/10`.

## 6. Interval computation settings for positive bases

`POSITIVE_SETTINGS` collects the following settings. Their complete exact values also appear in `supplement/common_settings.csv`.

| Parameter | Fixed value | Role and verification location |
| --- | --- | --- |
| `cap` | `369098752` | The finite upper bound for the scan of positive odd numerators `S` in `positive_families`; it is not the modulus |
| `grid` | `8192` | The terminal interval grid denominator `Q` |
| `size_grid` | `32768` | The denominator `R` used for size bins `floor(R*sigma)` in the joint counts |
| `denominator` | `10**9` | The common denominator `D0` for normalized integer lower-bound tables |
| `seed_exponent` | `13` | The initial scale `5**13` |
| `seed_width` | `14` | All first exponents in the initial integer representations must be less than 14 |
| `height_caps` | `(40,57,83,108,134)` | The terminal height caps `K_m` retained at successive steps |
| `seed_span` | `400` | The first interval width `W_1`, measured in grid units |
| `levels` | `5` | The number of terminal recurrence steps for positive bases |
| `width_increment` | `11` | The increment of 11 in `nu_m` at each step, giving a scale ratio of `P=5**11` |
| `span_increment` | `2` | The increment of 2 in `W_m` at each step, allowing for size-binning errors |
| `retained_heights` | `(15,28)` | Only nonzero residue-family contributions with heights in this closed interval are retained in lifting |

The initial computation covers positive odd integers `n<2*5**13`. In this fixed range, all terms are positive and `5**14>2*5**13`, so restricting the first exponent to be less than 14 does not omit any representation. This is not a guarantee for arbitrary choices of `seed_width`.

`next_intervals` requires the displacement error bound for size bins, the scale relation, and integer range checks. These settings are interdependent; changing an individual value does not guarantee that the original proof still applies. Discarding nonzero residue contributions outside `retained_heights` does not mean that no residues have those heights.

## 7. Computation ranges and memory settings

`CHUNK=250000` sets the number of array positions processed in each batch. Changing the batch size should not change the mathematical result, but the implementation must still satisfy checks such as uniqueness of residues within each batch and fixed-width integer bounds.

The general signed terminal construction uses the following window radii:

| Bases | `TERMINAL_LIMITS` |
| --- | --- |
| `(-2,3)` | `300000000` |
| `(-2,-3)`, `(-5,2)`, `(5,-2)`, `(-5,-2)` | `10000000` |

The construction retains only integers inside the window. Discarding paths that leave the window can only reduce the number of representations found, so this output is a lower bound. The window radius must still cover every requested `X`.

The cases `(7,-2)` and `(-7,-2)` use the one-term representations `1` and `p`, giving `T_1(7)>=2`, and do not use this window. The case `(5,2)` uses the interval recurrence for positive bases described above and likewise does not use this window.

The two height arrays for the full positive-base computation require approximately 2.27 GiB, in addition to the joint distribution and temporary arrays. Reducing `CHUNK` reduces temporary storage but does not eliminate the space required by the two height arrays.

## 8. Generating and checking the supplement

Run these commands from the program root:

```bash
python export_parameters.py
python export_parameters.py --check
```

The first command generates all Markdown and CSV files. The second checks, without writing, that these files agree with the current `parameters.py`; missing or altered files cause an error. Both commands use only the Python standard library and do not start large-scale residue or terminal computations.

The source data contain 8 base pairs, 71 period positions, 191 scales, 466 intervals, and 2426 interval choices. The generator exports every entry, using exact fraction text for all `Fraction` values. See the [parameter supplement](../supplement/README.md) for the complete case index.

The choices in the parameter tables can be verified, but the tables alone do not prove the result. A successful parameter export consistency check and a successful complete density verification are separate statements.
